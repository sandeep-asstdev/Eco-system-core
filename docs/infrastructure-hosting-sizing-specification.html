Multi-Tenant Automobile Dealership Software Ecosystem
Baseline Core Stack + 10 Additional Domain Applications (13 Total Apps)

Document Purpose: Technical requirement and infrastructure sizing specification prepared for IT infrastructure teams, cloud architects, and hosting providers. Outlines resource specifications for the active 3-app core and linear scaling required to host 10 additional domain applications on the unified platform.

1. Application Overview

What the Platform Does: An integrated, multi-tenant digital dealership operating platform engineered for multi-franchise automotive dealer groups, OEM retail franchise networks, and multi-brand conglomerates. It unifies corporate governance, Single Sign-On (SSO), Scoped Role-Based Access Control (RBAC), and transactional domain workflows across all dealership departments while preserving autonomous, decoupled service operations.

1.3 Architecture Pattern & Tiers Involved

  • Architecture Style: Containerized microservices orchestrated via Docker Compose / Kubernetes.
  • Edge / Ingress Tier: Nginx Reverse Proxy with TLS 1.3 termination, rate limiting, and gzip compression.
  • Identity & Auth Tier: Keycloak 24+ (Quarkus) OIDC cluster with RS256 token signing and PKCE.
  • Frontend Tier: Pure React 18 SPAs compiled to static bundles served behind Nginx/CDN.
  • Backend Microservice Tier: Node.js (Express) domain microservices with Prisma ORM.
  • Event Mesh Tier: RabbitMQ 3.13 cluster with durable Topic Exchanges and Dead-Letter Exchanges (DLX).
  • Cache & Worker Tier: Redis 7 cluster for session caching, rate limits, and BullMQ async queues.
  • Persistence Tier: PostgreSQL 18 High-Availability cluster with dedicated database-per-domain isolation.

6. Databases Architecture & Backup Strategy

  • Database Engine: PostgreSQL 18 (or PostgreSQL 16 LTS) with PgBouncer connection pooler in transaction pooling mode.
  • Isolation Strategy (Database-per-Domain): Each application maintains its own dedicated database (ecosystem_core_db, keycloak_db, hrflow_db, maintly_db, and separate databases for each of the 10 upcoming apps) to ensure complete data isolation and avoid noisy-neighbor locks.
  • High Availability (HA): Active Primary + Hot Synchronous Standby replica with automated failover via Patroni + etcd or AWS RDS Multi-AZ / Azure Flexible HA (RPO = 0, RTO < 30 seconds).
  • Backup & Retention: Continuous WAL archiving (Point-In-Time Recovery to any second for 14 days) + Nightly full snapshots at 02:30 AM (retained 30 days) + Monthly financial year-end archives retained for 7 years (tax compliance).

7. Network, Connectivity & Security

  • Internet Bandwidth: Launch: 50 Mbps burstable to 100 Mbps. 13-App Enterprise Scale: 200 Mbps committed bandwidth burstable to 500 Mbps – 1 Gbps (estimated 4–8 TB monthly egress).
  • Public IPs & SSL: 2 Public IPv4 addresses (for redundant Ingress Load Balancers) + 1 Wildcard SSL Certificate (*.dealershipecosystem.in) with TLS 1.3 encryption.
  • Branch Connectivity: Dealership showrooms and workshops connect over HTTPS (Port 443) through WAF. Biometric devices communicate via outbound HTTPS/MQTT or WireGuard/IPsec gateway. Optional Site-to-Site IPsec VPN to central DMS/SAP servers.
  • Security & WAF: Layer 7 Load Balancer + Web Application Firewall (OWASP Top 10, bot protection, geo-fencing to India regions, 30 req/sec rate limit per IP). Strict 3-tier network segmentation (Public DMZ → Private App Subnet → Isolated DB Subnet).
